## Resolved findings

- Whole-project revision conflicts blocked independent notes. Shared saves now use atomic conditional operations on records. Every touched record must match its captured original value, and the complete resulting project must pass reference and evidence validation. Independent notes can both save; same-note and delete/edit races stop without partial writes.
- Lost success responses could leave an ambiguous pending save. Operations and room creation now have stable IDs; the server persists content-hashed operation receipts in the same atomic replacement as project state. Retrying an already committed operation returns the current head without adding history or replaying the edit. Receipt IDs are never evicted; the 50,000-entry cap refuses new writes rather than weakening retry protection.
- Unsaved writing lacked durable recovery. Per-input local drafts now cover card notes, memos, comparison writing, code guidance, board groups and themes. Distinct immutable generation keys prevent an older recovery in another tab from deleting newer writing. Existing-note and memo recovery checks its original record; a changed record requires an explicit separate version.
- Slow acknowledgements could replace newer browser state. Acknowledgement reloads the latest workspace and uses its atomic revision check. It removes only the acknowledged pending ID and handles a session left in another tab, already acknowledged creation and legacy pending saves without adopting a stale response.
- Failed creation and empty edits could leave synchronization stuck. Creation retries precede room lookup, preserve the original room ID and survive reload. Empty record changes never create a dirty queue.
- Closing or switching a note editor could lose in-memory writing when draft storage failed. Close, Escape, source navigation, note switching and editor cancellation now require acknowledging the storage failure. Saving disables editor mutation; an already open card retains original context if the live card disappears.
- Stale code, memo, group and theme editors could replace changed records. Save and delete handlers compare the captured original record. Whole-graph validation still prevents dangling links. Missing evidence is handled defensively in the UI.
- Whole-project Undo could erase unrelated incoming edits. Undo now submits a conditional inverse for only the affected records, preserving unrelated edits and refusing changed records. Unresolved shared writes pause Undo. Persistent restore points remain explicit whole-project recovery.
- Conflict resolution could obscure the rejected writing. The review dialog presents local and shared versions, offers a pending-work download, preserves the complete local project before any resolution, and can append one conflicting note with a fresh ID. A removed source remains preserved in the local copy, without resurrecting it on the shared board.
- Conflict/recovery layout and feedback received keyboard, phone and axe checks. Recovery errors appear inside the active dialog, field labels use plain language, and dialog entry uses a transform rather than temporarily low-contrast opacity.

## Evidence and limits

See [TEST-RESULTS.md](../TEST-RESULTS.md) for the final suite and screenshots. Regression cases include independent and same-note races, delete/edit ordering, lost responses, retry after restart, offline dependent queues, stale tabs, delayed acknowledgements, generation-safe draft recovery, storage aborts, scoped Undo, old-format migrations and exact project round trips.

This is one-process, same-computer collaboration, not multi-server synchronization or remote hosting. Records are the concurrency unit; simultaneous field or character edits within one record require explicit resolution. Names are unverified. Draft and project exports are separate. Storage clearing, browser eviction, physical power loss and disk failure remain outside the tested recovery guarantee; file sync and atomic rename are not a claim of durable directory metadata under every power-loss scenario. Histories are bounded recovery points, not a permanent audit log.
